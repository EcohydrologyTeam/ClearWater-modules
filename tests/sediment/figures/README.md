# SSM diagnostic figures

This directory holds reproducible diagnostic figures generated from
the SSM (Sediment Simulation Module) reference datasets and from
coupled smoke-test runs.

## plan01_10x5 RAS-coupled smoke run

Four PNGs generated by `smoke_plot.py` visualize SSM behaviour when
coupled to ClearWater-Riverine on the `plan01_10x5` RAS HDF5 fixture
(49 real cells in a 10x5 layout, uniform initial bed, SAND2008
SEDflume bundle, 9 sediment classes). The scenario mirrors the
smoke test at
`tests/sediment/test_ssm_riverine_smoke.py::test_ssm_riverine_smoke_plan01_10x5`
but runs **10 SSM steps** (vs. 5 in the test) at a 60 s SSM step under
a sustained, spatially-uniform external bed shear of **tau_b = 4 Pa**
(comfortably above the SAND2008 fines tau_ce ~ 1.0-1.6 Pa). Bedload
is disabled (`bedload_solver="off"`) so the budget reduces to bed
<-> suspended only.

### `01_bed_mass_timeseries.png`

Per-cell total bed mass (g/cm^2, summed over all SEDZLJ layers) for
ten real cells sampled across the mesh. Under uniform 4 Pa shear and
a spatially-uniform initial bed every cell follows the same curve, so
the lines superimpose (this is expected: `plan01_10x5` has no spatial
heterogeneity in the bed initial condition). The downward slope
confirms erosion fires under sustained tau >= tau_ce, and the mass
loss is linear to within plotting resolution over a 10-step window.

### `02_bed_shear_spatial.png`

Scatter of tau_b at face centroids (`mesh.face_x`, `mesh.face_y`) at
the final step, colored 0-5 Pa with the `viridis` colormap. With the
`external` shear driver writing 4 Pa to every real cell every step,
all 49 dots are essentially the same color (~4 Pa). The figure is a
sanity check that (a) the shear field plumbs through to the SSM mesh
diagnostics and (b) the spatial layout of `plan01_10x5` is what we
expect (10 columns x 5 rows, with one missing cell in the bottom row
giving the 49 count).

### `03_armoring_class_fractions.png`

Stacked-area plot of the **surface-layer per-class mass fraction**
for the cell with the largest bed-mass loss across the window
(cell 0 by default; they are all equally eroded so the tie-break
wins). Class labels are `class_0` ... `class_8`, ordered fine ->
coarse from the SAND2008 bundle. Over 10 steps the surface composition
is essentially unchanged: at 60 s/step x 10 steps = 600 s of erosion
at 4 Pa, the fraction of bed mass actually removed is < 0.3 % of the
in-place layer, so the surface composition does not visibly armor.
**Caveat:** this short visualization is **not** a validation of the
armoring algorithm; it only confirms the diagnostic plumbing is
wired. To see armoring in action, run for thousands of steps or ramp
tau to ~10 Pa where the fines drain faster than the active layer
reorganizes.

### `04_mass_conservation.png`

Conservation of the bed/bedload/suspended mass budget, all expressed
as **change since t = 0** in cell-summed g/cm^2. Three signals plus
their algebraic sum:

  - **Delta bed mass** (blue): drops linearly under sustained erosion.
  - **Delta bedload mass** (gray, dotted): flat at 0 because
    `bedload_solver="off"` in this scenario.
  - **cum source Sum dt(E - D)** (red): the per-class net source SSM
    stages on the mesh for Riverine, summed over classes and steps.
    This is the mass leaving the bed per the SSM accounting.
  - **Sum check** (dashed black): the algebraic sum of the three
    above. In a closed budget it should be ~ 0.

The sum-check sits at +1.34 g/cm^2 (~ 0.03 % of the ~4188 g/cm^2
initial bed mass). The non-zero offset comes from the **first** step,
when SSM's deposition path injects a small per-class deposition flux
from the (zero) suspended concentration before any erosion has filled
the column. After that first step the slope of the sum line is near
zero, so per-step conservation holds at float32 precision. The shaded
grey band is a +/-1 % visual tolerance; the annotation reports the
suspended-tracer mass, which is 0 g in this scenario because the
smoke-test `tracer` constituent has zero IC/BC and no SSM-registered
suspended class carries an IC/BC into Riverine.

### Reproduction

```bash
conda activate clearwater
python tests/sediment/figures/smoke_plot.py
```

The script uses absolute paths and can be run from any cwd. It will
exit with a clear message if the sibling ClearWater-Riverine-streaming
repo or the SAND2008 SEDflume fixture is missing.

### Caveats

- 5-10 SSM steps is well below what is needed to demonstrate steady
  bed armoring or full PSD evolution; treat these plots as
  smoke-level visualizations, not physical validation.
- The `plan01_10x5` fixture has no spatial heterogeneity in initial
  bed composition or velocity field, so per-cell signals (figures 01,
  02) are spatially uniform.
- The `external` shear driver writes a constant 4 Pa to every cell;
  for a current-driven tau field we would need a fixture that exposes
  per-cell velocity and depth (which `plan01_10x5` does not).

## SAND2008 ENRATE cross-check

Two figures cross-check SSM's `SedflumeTableErosionModel` interpolation
against the published SAND2008-5621 ENRATE table that ships with the
example dataset under `tests/sediment/data/sand2008_example/`.

### `05_sand2008_erosion_curves.png`

Erosion rate (cm/s, log axis) vs. bed shear stress tau (Pa) for the
eight size interpolants of the SAND2008 example. Solid colored lines
are SSM's bilinear-in-tau interpolation evaluated on a continuous
tau sweep from 0.5 to 21 Pa; filled markers at tau in {0, 2, 4, 8, 10, 20}
Pa are the published `bed.sdf` ENRATE values. A thin black dashed
line shows the per-cell `SedflumeTableErosionModel` evaluated against
the deepest in-place ENRATE row (the v1 active-layer fallback tiles
this row across all size classes). Lines and markers coincide at the
table tau levels by construction; between table levels SSM uses linear
interpolation in tau.

### `06_sand2008_residuals.png`

Relative error `(computed - published) / published x 100 %` for each
size interpolant, evaluated AT each of the six table tau levels. A
gray band marks the +/- 1 % unit-test tolerance from
`test_sedflume_table_returns_known_rates_at_table_taus`. All eight
classes return exactly 0 % error at every table tau level, confirming
that SSM's interpolation is faithful to its input table (correctness
gate: should be < 0.1 %).

### Reproduction

```
python tests/sediment/figures/sand2008_plot.py
```

(from the repo root, with the package importable, e.g. installed in
editable mode or with `PYTHONPATH=src`).

Note: the cross-check is at the table tau levels, where the published
table is the input to the interpolator and is recovered exactly.
Intermediate tau values are linear interpolations and are expected to
deviate slightly from any independent ground truth — the published
table is the input to SSM, not an external reference at off-table taus.
